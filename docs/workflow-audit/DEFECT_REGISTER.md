| WF-001 | High | Mobile sign-in from a physical device returned `Network Error`. | Backend could not start because port 3000 was occupied; the device URL itself did not require an `/api` suffix because the shared API client adds the prefix. | Runtime/process issue documented during diagnosis; API contract check now verifies route prefixes. | None |
| WF-002 | High | Approving the first KYC document removed the remaining rows and borrower stayed pending. | Admin treated files as independent submissions and account/document states diverged. | KYC decisions now update the complete grouped submission, canonical user state, borrower profile, notification, and realtime event atomically. | WF-003 | Medium | Rejected users had to sign in again and received no actionable result. | No authenticated resubmission/status contract and no deterministic rejection notice. | Added `/api/kyc/my-submission` and authenticated `/api/kyc/resubmit`; notification deep-links to `kyc-resubmit`. Emulator E2E covers existing-session reuse. | None |
| WF-004 | High | A suspended user could continue using a previously issued JWT. | JWT strategy trusted stale token role/account claims. | Strategy reloads canonical account and roles on every guarded request. Unit tests cover active, suspended, deleted, and removed-role users. | None |
| WF-005 | High | Borrower/lender endpoints accepted caller-supplied owner IDs. | Several controllers lacked role guards or trusted path/query ownership. | Added borrower/lender guards and canonical request-user ownership checks; cross-account claims return 403. | None |

| WF-007 | Medium | Admin client contained an obsolete ad-status endpoint. | Duplicate API client drifted from Nest controllers. | Removed dead caller and added route inventory/required-contract validation across both clients. | None |
| WF-008 | Low | Lender ads service exceeded the architecture limit. | Validation and persistence responsibilities accumulated in one service. | Extracted lender-ad validation; architecture check passes. | None |
| WF-009 | Medium | Original E2E suite was `Hello World` and could contact configured Firebase. | No isolated integration harness or mutation safety assertion. | Emulator-only setup aborts without `FIRESTORE_EMULATOR_HOST`; full auth/KYC journeys use deterministic external mocks. | None |
| WF-010 | Medium | Dependency installation reported critical/high npm advisories. | Old Firebase Admin, Puppeteer, bcrypt, React Router, and Expo build-tool dependency trees. | Upgraded the compatible backend/web packages. | WF-011 | High | Two rapid application submissions could create duplicate active applications. | Duplicate detection used a read-then-write query without a retry-stable key. | Application creation now uses a deterministic submission key in the same transaction; API E2E proves a retry returns the original application. | None |
| WF-012 | High | A QR payment retry could consume its nonce before the installment ledger write succeeded. | QR verification and settlement were separate writes. | Nonce validation, deterministic ledger creation, installment/loan updates, and nonce consumption now share one Firestore transaction. | WF-013 | High | A successful PayHere callback updated the order but did not settle the canonical installment ledger. | Provider status and internal payment state had separate owners. | Valid callbacks call the idempotent core-ledger settlement before completing the order; callback retries return the existing result. Unit coverage verifies the hand-off. | None |
| WF-014 | Medium | AI tools could report KYC from a seed-only collection that disagreed with the product UI. | The tools queried `kycSubmissions` instead of the canonical user and secured document records. | Borrower/admin AI tools now use `users.kycStatus` and `documents`; the canonical-state contract check and unit suite cover the service. | KYC consistency backfill can repair legacy user/profile mismatches. |
| WF-015 | Medium | Isolated agreement E2E returned 503 during signing. | The secure acceptance audit hash intentionally fails closed without a 32+ character salt, but the emulator harness omitted the test value. | Added a deterministic test-only `LEGAL_AUDIT_HASH_SALT`; production still requires its own secret. | WF-016 | Critical | Borrower profile password/email changes appeared successful but the old login credential remained active. | The mobile screen used a demo OTP and the backend wrote an unused password field on `users`, while authentication reads the bcrypt hash in `authCredentials`. | Removed demo verification, require the current password, enforce email uniqueness, and atomically update the canonical user and credential records. | WF-017 | High | Lenders could not reach KYC/resubmission or change their password from the profile. | KYC screens were absent from the lender navigator/profile, and the password service deliberately threw an unsupported-operation error. | Registered both KYC routes, added the profile entry and rejected-state action, and connected password changes to the canonical auth endpoint. Mobile type-check and authenticated API E2E cover the contract. | None |
